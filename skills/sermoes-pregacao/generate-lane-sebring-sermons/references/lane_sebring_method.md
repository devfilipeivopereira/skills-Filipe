# Lane Sebring Sermon Method

Use this reference when the user wants a sermon built around Lane Sebring's preaching framework from Preaching Donkey, with problem-first structure, a bottom-line bridge, practical application, and explicit Gospel pivot.

## Core Formula

Effective preaching combines:

- information
- inspiration
- application

Information without inspiration is boring.
Inspiration without application is useless.

## Personality and Context

The framework should fit the preacher's personality and the audience's actual needs.

Do not force a one-size-fits-all delivery.

## Preparation Before Writing

### Objective

Define what the sermon does.

Examples:

- shows how identity in Christ changes relationships
- teaches how to pray
- demonstrates how a passage points to Jesus

### Desired Response

Define what the listener should do in response.

Examples:

- take a concrete step in living from identity in Christ
- begin a daily prayer rhythm
- start giving financially

### Know, Feel, Do

Test the sermon against three questions:

- what should the audience know?
- what should they feel?
- what should they do?

If one test fails, the sermon is not ready.

## Foundational Theory

Pathos precedes logos.

The audience needs to feel the problem before they will want the solution.

## Four Main Stages

### 1. Present the Problem

Start with a relatable problem before the text.

Rules:

- do not start with the text
- do not start with context
- do not start with technical doctrine

Emotional arc:

- light and accessible
- increasingly relatable
- increasingly weighty

The goal is to get everyone on the hook for the solution.

### Bridge: Bottom Line

Reveal the bottom line before going to the text.

The bottom line should be:

- short
- repeatable
- experiential, not merely abstract

After presenting it, move into the text as the answer.

### 2. Solve the Problem with the Text

Present the text as the answer to the problem.

Use minimal, functional biblical context. Enough to create credibility, not enough to stall momentum.

### 3. Equip the Listener to Apply It

Every point should be action-oriented.

For each point:

- explain it
- apply it
- illustrate it

The points are practical expressions of the bottom line.

Application should be woven throughout the message.

### 3b. Gospel Pivot

At this stage, point explicitly to the Gospel.

Without this pivot, application turns into moralism.

The power to live the truth comes from Christ in the listener, not from willpower alone.

### 4. Cast Vision and Inspire

Use `imagine` language.

Show:

1. what could happen personally
2. what could happen in the church
3. what could happen in the world beyond the church

Declare the congregation's identity, not just its duty.

End with one specific, immediate action step.

## Additional Delivery Guidelines

- keep sermons short and edited
- avoid artificial alliteration
- enter illustrations directly without awkward setup
- use notes sparingly
- avoid weak endings that summarize without landing application

## Default Deliverable

Unless the user requests a different format, produce:

1. Pre-sermon declaration with the five required statements.
2. Complete sermon manuscript.
3. One clear immediate next step.
4. A formatted `.docx` file that passes the minimum word count threshold.

## Word Document Requirement

- The standard output is a Microsoft Word `.docx` document.
- For a complete sermon, enforce at least 7,500 words unless the user explicitly changes the requirement.
- Build the manuscript first, then convert it to `.docx`.
- Confirm the final word count before treating the job as complete.
