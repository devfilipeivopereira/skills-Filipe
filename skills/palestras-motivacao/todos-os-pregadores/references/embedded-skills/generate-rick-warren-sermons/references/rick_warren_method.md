# Rick Warren Sermon Method

Use this reference when the user wants a sermon built around Rick Warren's methodology, the CRAFT process, Saddleback-style sermon flow, or purpose-driven preaching.

## Central Philosophy

Evaluate the sermon by whether it motivates people to develop:

1. Christlike convictions: think like Jesus.
2. Christlike character: feel like Jesus.
3. Christlike conduct: act like Jesus.

If the sermon does not move the listener toward transformation in thought, emotion, and behavior, it is incomplete.

## CRAFT Process

### C: Collect and Compare

- Gather biblical material related to the theme or text.
- Note illustrations, cross-references, tensions, and repeated ideas.
- Group verses and observations by subtheme before outlining.

### R: Research and Reflect

- Study context, genre, grammar, and theological meaning.
- Reflect devotionally on what God is saying to the preacher, not just to people in general.
- Let personal conviction shape the tone of the sermon.

### A: Apply and Arrange

- Develop both individual and corporate application.
- Order the points for persuasion and hearability, not only by text sequence.
- Build tension, release, and movement.

### F: Fashion and Flavor

- Use action verbs in point titles.
- Prefer concrete nouns: benefits, marks, steps, choices, habits.
- Address the listener as `voce` in personal application.
- Plan illustrations intentionally to maintain attention.

### T: Trim and Tie Together

- Cut filler aggressively.
- Use clear transitions with category words.
- Make the structure easy to repeat after the sermon ends.

## Sermon Structure

### 1. Hook

- Start with a human need.
- Do not begin with the biblical text.
- Good openings may use a question, relatable situation, surprising statistic, or paradox.

Common entry-point needs:

- stress and anxiety
- relationship conflict
- lack of purpose
- loneliness
- financial pressure
- shame or failure
- fear of the future
- guilt from the past

### 2. Bridge

- Show that Scripture speaks to the need raised in the opening.
- Briefly set the context of the passage.
- Use accessible Bible wording when possible.

### 3. Application Points

Prefer 3 to 5 points, usually 4. Each point should contain:

1. Action-title with verb.
2. Clear biblical support.
3. Explanation of meaning.
4. Illustration or story.
5. Specific application in second person.

Use fill-in markers where helpful:

`[ESPACO PARA PREENCHIMENTO: ______________]`

Retention devices are encouraged:

- alliteration
- acronyms
- repeatable categories

### 4. Commitment Prayer and Homework

The prayer should help the listener verbalize:

- what was learned
- what will change
- where help is needed

The homework must be:

- specific
- verifiable
- bound to a time window, usually before next Sunday

## Pre-Writing Checklist

- What concrete human need does this sermon address?
- Which transformation target is primary: convictions, character, or conduct?
- What is the core statement in one sentence using `voce`?
- Are the points action-led?
- Does the point order follow persuasion rather than verse order?
- Does the sermon create tension, release, and movement?
- Does each point include an illustration?
- Is the language lean?
- Are transitions explicit?
- Is the homework measurable and time-bound?

## Point-Level Checklist

- Starts with an action verb.
- Uses second-person application.
- Includes biblical support.
- Includes concrete illustration.
- Includes specific application.
- Advances transformation.

## Default Deliverable

Unless the user requests a different format, produce:

1. Pre-sermon declaration with the five required statements.
2. Complete sermon manuscript.
3. Commitment prayer.
4. Homework for the week.
5. A formatted `.docx` file that passes the minimum word count threshold.

## Word Document Requirement

- The standard output is a Microsoft Word `.docx` document.
- For a complete sermon, enforce at least 7,500 words unless the user explicitly changes the requirement.
- Build the manuscript first, then convert it to `.docx`.
- Confirm the final word count before treating the job as complete.
