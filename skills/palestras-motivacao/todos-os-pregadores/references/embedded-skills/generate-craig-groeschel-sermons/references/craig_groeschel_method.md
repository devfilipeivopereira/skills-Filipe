# Craig Groeschel Sermon Method

Use this reference when the user wants a sermon built around Craig Groeschel's authentic style, with one central idea, a repeated phrase-mantra, numbered sentence-points, strong vulnerability, emotional momentum, and science plus Scripture integration.

## Core Identity

Groeschel is a strategic communicator who uses Scripture and science together to move people toward action.

The audience may include:

- mature Christians
- new believers
- skeptics
- nonbelievers
- online viewers
- multi-site congregations

The message should feel like a personal conversation that scales to a massive audience.

## Central Principle

Emotion moves people more than knowledge alone.

Every section should create emotional connection, not just deliver information.

## One Core Idea

Before writing, determine:

1. what is one thing the audience must know?
2. what should they do with it?

The numbered points serve one idea, not multiple sermon ideas.

## The 4 Ps

### Practical

- give specific application
- make it time-bound
- answer what the listener will do differently tomorrow

### Personal

- use raw, specific vulnerability
- share real internal dialogue
- make the confession recent and risky

### Memorable

- write every point as a full sentence
- create a repeatable phrase-mantra
- repeat the key line several times

### Emotional

- create an emotional peak in each major section
- use pauses and tension before resolution
- aim for hope, grace, courage, relief, conviction, belonging

## Resistant Listener Filter

For every point, answer:

- why does this matter?
- so what changes for the listener?
- why might someone think this does not apply to them?

If those are weak, rewrite.

## Science Plus Scripture

At least once in the sermon, connect biblical truth to scientific or psychological insight in a way that reinforces credibility and accessibility.

Example shape:

- Scripture names the reality
- science confirms the mechanism
- God knew the truth first

## Vulnerability Standard

The vulnerability should be:

- specific
- recent
- risky
- universal in implication
- resolved by biblical truth

Do not settle for generic admissions.

## Point Structure

Use 3 to 5 numbered points.

Each point must:

- be a complete sentence
- stand alone in memory
- support the same central idea

Common flows:

- diagnosis -> remedy
- problem -> truth -> action
- progressive action steps

## Interaction Design

Include audience participation naturally:

- hands raised
- reflection prompts
- short diagnostic exercises
- direct acknowledgement of online or multi-site listeners

## Full Sermon Flow

### Opening

Open with recent, high-specificity vulnerability.

End the opening with a shared question and acknowledge the wide audience context.

### Central Idea and Phrase-Mantra

- state the phrase clearly
- say how many points are coming
- address the skeptic directly when helpful

### Point 1: Diagnosis

- state the point as a full sentence
- add science or psychology
- confirm with Scripture
- add personal vulnerability
- interact with the audience
- answer likely resistance

### Point 2: Revelation

- state the point as a full sentence
- guide the text
- connect to point 1
- bridge science and Bible if fitting
- add story or dramatized scriptural support
- repeat the phrase-mantra

### Point 3: Activation

- state the point as a full sentence
- give dated practical steps
- add an exercise if useful
- address `but not me`
- apply to multiple demographics
- include personal accountability

### Climax

- repeat the phrase-mantra with highest emotional force
- challenge immediate response
- add a short transformation story
- build emotional intensity with restraint and pauses

### Ending

- summarize the points quickly
- repeat the phrase-mantra again
- give one next step
- acknowledge multi-site and online listeners
- add a brief conversational prayer

## Default Deliverable

Unless the user requests a different format, produce:

1. Pre-sermon declaration with the five required statements.
2. Complete sermon manuscript.
3. One clear weekly next step.
4. A formatted `.docx` file that passes the minimum word count threshold.

## Word Document Requirement

- The standard output is a Microsoft Word `.docx` document.
- For a complete sermon, enforce at least 7,500 words unless the user explicitly changes the requirement.
- Build the manuscript first, then convert it to `.docx`.
- Confirm the final word count before treating the job as complete.
