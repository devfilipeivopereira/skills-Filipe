# Andy Stanley Sermon Method

Use this reference when the user wants a sermon built around Andy Stanley's authentic communication method from `Communicating for a Change`, with one point, one Bottom Line, and the `ME-WE-GOD-YOU-WE` map.

## Core Identity

Stanley is a strategic communicator oriented toward behavior change.

The sermon is designed for a mixed room:

- practicing Christians
- nominal Christians
- skeptics
- people hurt by church

The message should be:

- accessible
- relevant before religious
- relational before instructional
- memorable before comprehensive

## Imperative 1: The One Point

Before structuring anything, answer:

1. What is one thing the audience must know?
2. What should they do with it?

Everything else serves that point.

## Imperative 2: Bottom Line

The Bottom Line is the short, memorable expression of the one point.

It should be:

- short
- memorable
- actionable

Use it this way:

1. build it before writing the sermon
2. reveal it near the end of GOD
3. repeat it naturally in YOU and final WE
4. land on it at or near the close

The communicator must also carry a real burden. If there is no deep compulsion to reach the key moment, the sermon is not ready.

## Imperative 3: ME-WE-GOD-YOU-WE

This is a journey map, not a content outline.

### ME

Start with a specific, active dilemma from the communicator's life.

Requirements:

- concrete
- vulnerable
- conversational
- slightly self-deprecating when fitting

Do not start with a topic statement.

### WE

Expand the personal dilemma into the audience's shared struggle.

Requirements:

- build real tension
- use rhetorical questions
- show the cost of leaving the tension unresolved
- include multiple audience profiles

Do not move to GOD until the audience wants the answer.

### GOD

Reveal what God says about the tension through one main text.

Requirements:

- one central biblical text
- guide the audience through the text rather than dumping it
- comment while reading when helpful
- surface unusual details and anticipated objections
- verbalize the skeptic's questions when necessary
- summarize the truth clearly before leaving the text

Reveal the Bottom Line near the end of GOD.

### YOU

Move from what God said to what the listener must do.

Requirements:

- application must be specific
- include real-life timing and behavior
- consider different listener types
- address the nonbeliever directly when useful
- keep one primary application step
- show that this also applies to the communicator

### Final WE

Paint the picture of what could happen if everyone lived this truth.

Requirements:

- return to `we`
- use `imagine` and `what if` language
- be concrete about who benefits
- do not simply summarize

## Delivery Principles

- conversational tone
- dry humor
- rhetorical questions
- explicit transitions
- argue the case as if something important is at stake

Write transitions explicitly:

- ME -> WE
- WE -> GOD
- GOD -> YOU
- YOU -> WE

## Introduction Questions

When shaping ME, answer:

1. What question am I answering?
2. What tension am I resolving?
3. What mystery am I solving?

## Text Questions

When shaping GOD, answer:

- what do they need to know?
- why do they need to know?
- what do I want them to do?
- why should they do it?

## Default Deliverable

Unless the user requests a different format, produce:

1. Pre-sermon declaration with the five required statements.
2. Complete sermon manuscript.
3. One clear weekly action step.
4. A formatted `.docx` file that passes the minimum word count threshold.

## Word Document Requirement

- The standard output is a Microsoft Word `.docx` document.
- For a complete sermon, enforce at least 7,500 words unless the user explicitly changes the requirement.
- Build the manuscript first, then convert it to `.docx`.
- Confirm the final word count before treating the job as complete.
